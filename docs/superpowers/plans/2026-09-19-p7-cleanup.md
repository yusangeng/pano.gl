**三个决定：**

| 决定 | 理由 |
|---|---|
| `sideEffects: false` | 全库没有模块级副作用（P1 的 `src/index.ts` 只做 re-export）。**这一行是打包器做 tree-shaking 的前提**，少了它消费者会把整个库拖进去。 |
| `exports` 映射含 `types` | `types` 必须是每个条件分支的**第一条**。放错顺序 TypeScript 会拿到 JS 文件当声明文件，报「找不到类型」。 |
| `engines: node >= 20` | Node 18 已 EOL，而 `crypto.randomUUID()` 在全局可用是 Node 19+。 |

> **`version` 到 1.0.0** —— 这是 P5 冻结的公开 API，P6 只加了一个后端，没有改接口。

**devDependencies 与 scripts 一律取 P1 写的范围**，工具链是 P1 定义的，这一期只做减法。上面那块**不是重新设计的**，是 P1 Task 2 的 `package.json` 去掉 `build:legacy`（Task 2 删了 `scripts/legacy-build.mjs`，这条脚本已经没有对应的文件）之后的原样 —— **照抄 P1 的实际产出，不要照抄这份计划**：P1 执行时 `npm i` 装到的是当时的 latest，写进 `package.json` 的范围可能与这里略有出入，**以仓库里的实际文件为准**。

> **（2026-09-20 勘误，P1 终末全分支审查 IMPORTANT #3；协调侧预补，tsup 残留已就地改正）**：本 plan 撰写于 P1 的 tsup 方案时期，P1 执行中拍板换成了 **vite lib mode**（2026-09-20 用户裁决，见 P1 plan 文件头）。上方 JSON 块与两处正文里的 4 个 tsup 引用（`"build": "tsup"`、`"tsup": "^8"` devDependency、Task 3 的 `tsup.config.ts` 对齐段、Task 6 Step 3 的 minify 口径段）已全部改为 vite 事实——`"build": "vite build"`、`vite-plugin-dts: ^5`（P1 实际解析 `^5.1.1`）、对齐对象 `vite.config.ts`、`minify: false` 是显式裁定而非默认。**与 P1 实际落地 package.json 的其余已知差异**（本块未逐一改写，上方「以仓库里的实际文件为准」的告诫对它们生效，这里点名防照抄）：`typecheck` 实际是**三条**（根 + `test/integration` + `tsconfig.scripts.json`，P1 Task 8）；`lint` 实际带 `"demo/**/*.ts"` glob（P1 Task 6 5b / Task 10 I-1，P2 Step 9a 会再并入 `scripts`）；devDependencies 实际还有 `@types/node: ^22`（P1 Task 6 5a）；P1 Task 4 Step 2 还落了 `prepublishOnly` / `bugs` / `publishConfig.tag: alpha` 三条发布加固，本卡重写 `version` 为 `1.0.0` 时 `publishConfig` 应随 GA 决策一并处理而非默默照抄。

**三个与旧写法不同的地方，每一个都是浏览器模式带来的：**

| 字段 | 为什么是这个值 |
|---|---|
| `test:integration` 带两个 `--project` | `integration`（真 GPU + 守卫）和 `no-webgpu`（`--disable-gpu`，P6 的降级路径）是两个 project，只带一个就等于有一半集成测试从来不跑 |

**没有 `@playwright/test`，只有 `playwright`。** 前者是旧的测试 runner，整套断言与 fixture 都随浏览器模式切换一起删了；后者留着是因为它是 `@vitest/browser-playwright` 的 **peer dependency** —— 浏览器模式的 provider 靠它起浏览器，与「用不用它的 runner」无关。**这两个包名字像、作用完全不同，删错一个集成测试就连浏览器都起不来。**

```markdown
| 0.2.x | 1.0.0 |
|---|---|
| `'perspective'` | `{ kind: 'linear' }` |
| `'cylindrical'` | `{ kind: 'cylindrical' }` |
```

```bash
npx knip --include files,exports,types,dependencies
```

Expected: 无输出。

**`knip` 是一次性的检查，不进 CI**（它误报多，进了 CI 会被加一堆 ignore，然后就没人看了）。**跑一次，处理掉真问题，然后把 `knip` 本身卸掉。**

**它会报的一类真问题**：`src/index.ts` 导出了某个类型但没有任何测试或文档引用它。要么删，要么加进 README —— **「公开 API 冻结」意味着导出的每一样东西都有人依赖，多导出的类型也是承诺。**

- [ ] **Step 2: 依赖方向**

分层规则（`foundation` < `domain` < `app` < `ui`）不能有反向依赖：

```bash
# core/ 不许 import 别的层
git grep -n "from '\.\./\(media\|interaction\|viewer\|renderer\)/" -- src/core/ || echo "clean: core"
# media/ 不许 import 上层
git grep -n "from '\.\./\(interaction\|viewer\)/" -- src/media/ || echo "clean: media"
# interaction/ 不许 import 上层
git grep -n "from '\.\./viewer/" -- src/interaction/ || echo "clean: interaction"
```

Expected: 三条 `clean:`

**`renderer/` 不在链条里** —— 它是 `core/` 的消费者，被 `viewer/` 使用，和 `media/` 平级。**它唯一有权 import 的是 `core/`。**

- [ ] **Step 3: 包体积**

```bash
npm run build
ls -la dist/
gzip -c dist/index.js | wc -c
```

**量的口径要说清**：P1 的 `vite.config.ts` 显式写了 `minify: false`（lib mode 默认 minify on，P1 Task 4 质量审查裁定关掉），产物里也没有 `.min.js` —— 量的就是 ESM 产物 `dist/index.js` 的 gzip 体积，因此这个数偏保守（消费者自己会 minify）。

**记下这个数，写进 README。** 一个渲染库的体积是使用者选型时会看的东西，而且**它现在是个具体的数，不是「很小」**。
