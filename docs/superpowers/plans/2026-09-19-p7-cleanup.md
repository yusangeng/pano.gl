**三个决定：**

| 决定 | 理由 |
|---|---|
| `sideEffects: false` | 全库没有模块级副作用（P1 的 `src/index.ts` 只做 re-export）。**这一行是打包器做 tree-shaking 的前提**，少了它消费者会把整个库拖进去。 |

```markdown
# Migrating from pano.gl 0.2.x to 1.0.0

1.0.0 is a rewrite. The public surface is smaller and the constructor options
changed. There is no compatibility shim: the shapes were close enough that a
shim would have preserved the parts worth changing.

## Constructor options

| 0.2.x | 1.0.0 | Note |
|---|---|---|
| `el` | `container` | The same element, under the name the rest of the ecosystem uses. |
| `src` | `src` | Unchanged. |
| `projection: 'equiprectangular'` | `projection: 'equirectangular'` | **The old value was misspelled.** The correct spelling is now the only accepted one. |
| `projection: 'fisheye'` | —— | Throws at construction. It never worked: the legacy shader sampled `vec2(0.0, 0.0)` for every fisheye pixel, and the JS path threw. |
| `frameSize` | —— | Deleted. It existed to work around WebGL1's power-of-two texture rule, which neither WebGPU nor WebGL2 has. |
| `camera: { type, ... }` | `camera: { kind, ... }` | See below. |

## Camera types

| 0.2.x | 1.0.0 |
|---|---|
| `'perspective'` | `{ kind: 'linear' }` |
| `'cylindrical'` | `{ kind: 'cylindrical' }` |
| `'planet'` | `{ kind: 'planet' }` |
| `'pannini'` | `{ kind: 'pannini' }` |

`'ortho'` was never a public option; it is gone entirely.

## Behaviour changes

**Non-linear cameras now respond to latitude.** In 0.2.x, setting
`povLatitude` on the cylindrical, planet and pannini cameras had no effect:
the uniform was uploaded and the shader never read it. It does now. If your
application was compensating for the old behaviour by rotating the image
itself, remove that compensation.

**This is the only intentional behaviour change in 1.0.0.** Everything else
renders to the same pixels, which is what the migration's three pixel gates
were for.

## 事件

`on('*', handler)` 不再存在 —— 它转发一切，包括你不想接的。改为按名字订阅；`on()` 返回你自己的取消函数，不再需要记住 `off` 的签名。

## 渲染后端

1.0.0 优先 WebGPU，没有则降到 WebGL2。检查 `viewer.capabilities.backend` 可知道用了哪个。**两者渲染同样的像素**（门禁 C 断言 ±2 LSB）。

## 清理

`dispose()` 仍然是必须的，而且现在真的会释放资源：WebGL2 走 `WEBGL_lose_context`（0.2.x 从不释放上下文，创建 16 个 viewer 后新的就静默失败），DOM 监听走 `AbortController`（0.2.x 的 `removeEventLstener` 拼错了，resize 监听从来没被移除过）。
```

- [ ] **Step 1: 写 workflow**

`.github/workflows/ci.yml`：

```yaml
name: CI

on:
  push:
    branches: [master]
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm

      - run: npm ci

      - run: npm run typecheck

      - run: npm run lint

      - run: npm run test:coverage

      - run: npx playwright install --with-deps chromium

      # No flags and no environment here, and that is deliberate. P1 measured
      # that the thing which decides whether WebGPU exists is *which browser
      # binary Playwright launches*: `channel: 'chromium'` in
      # playwright.config.ts. The default `chrome-headless-shell` has no GPU
      # stack at all, so requestAdapter() returns null and every WebGPU test
      # takes the WebGL2 path while still passing.
      #
      # A `PLAYWRIGHT_CHROMIUM_ARGS` env var would do nothing whatever --
      # launch flags come from `use.launchOptions.args` in the config, and no
      # config reads that variable. Setting it would only look like the run was
      # configured, which is worse than an obviously missing setting. The guard
      # in test/integration/support/fixtures.ts is what makes the failure loud.
      - run: npm run test:integration

      - run: npm run build

      # P1's unit job asserted this, and the whole point of the rewrite is
      # that the published artifact has no unresolved external requires (the
      # legacy lib/ shipped require('../shader/vshader.glsl') calls).
      - name: the published artifact must load in plain node
        run: |
          node -e "import('./dist/index.js').then(m => console.log('esm ok'))"
          node -e "console.log('cjs ok', typeof require('./dist/index.cjs'))"

      # A WebGPU library that silently ships without WebGPU support is the
      # failure this step exists to catch. The assertion is in the test suite,
      # but a green suite that never reached the WebGPU path looks identical
      # to a green suite that did.
      - name: assert the WebGPU path actually ran
        run: |
          if grep -rq "skipped: no webgpu adapter" test-results/ 2>/dev/null; then
            echo "integration tests fell back to WebGL2; WebGPU was not exercised"
            exit 1
          fi

      - uses: actions/upload-artifact@v4
        if: failure()
        with:
          name: playwright-report
          path: playwright-report/
```

```js
/*
 * Fails the coverage run when branch coverage is under the 90% floor.
 *
 * vitest.config.ts (P1) carries the same 90% thresholds, but a number that
 * only exists inside a report is a number nobody reads. This makes the gate
 * an exit code.
 */

import { readFileSync } from 'node:fs'

const SUMMARY = new URL('../coverage/coverage-summary.json', import.meta.url)
const THRESHOLD = 90

const { total } = JSON.parse(readFileSync(SUMMARY, 'utf8'))
const branch = total.branches.pct
console.log(`branch coverage: ${branch}%`)

if (branch < THRESHOLD) {
  console.error(`branch coverage ${branch}% is below the ${THRESHOLD}% floor`)
  process.exit(1)
}
```
