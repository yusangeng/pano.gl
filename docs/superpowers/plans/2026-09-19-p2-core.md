# P2 — core 纯逻辑 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development（无 subagent 则 executing-plans）；收尾走 superloop 的 task-finish，禁用 finishing-a-development-branch。

**Goal:** 把「相机状态 + 投影参数 → 矩阵」和「屏幕坐标 → 等距柱状 UV」这两件纯计算做出来，并且**用 P0 的 uniform 流证明它跟旧实现一致**。不碰 GPU、不碰 DOM。

**Architecture:** `src/core/` 是零依赖的纯逻辑层。深度约定（GL 的 `[-1,1]` vs WebGPU 的 `[0,1]`）不在这里 —— 它由 `DepthRange` 参数注入，实现上直接选用 `gl-matrix` 的 `perspective`/`perspectiveZO` 两套 API。投影类型常量放在一份 JSON 里，TS 侧与着色器侧都由它生成。

**Tech Stack:** TypeScript 5 (strict) · gl-matrix · vitest

**为什么这一层能在没有渲染器的时候就被验证：** P0 存下了每一帧实际发给 GPU 的矩阵。矩阵是 CPU 算出来的 —— 所以 `core/` 的正确性**不需要任何 GPU** 就能对拍。这是 P0 把 uniform 流一并捕获的全部理由。

`src/core/constants.ts`：

```ts
/**
 * Projection kind constants.
 *
 * The numbers live in `projection-kinds.json` and nowhere else. Both this
 * module and the shader-constant generator read that file, so the JS side and
 * the shader side cannot drift -- which is exactly what went wrong in the
 * legacy implementation, where the same four numbers were declared
 * independently in `projectionType.js` and in `fshader.glsl`.
 */

import kinds from './projection-kinds.json'

/**
 * Camera projection kinds, uploaded as `u_CamProjType`.
 *
 * The names are PascalCase here and SCREAMING_SNAKE in the generated shader
 * constants; both derive from the same JSON keys.
 */
export const CameraProjection = {
  Linear: kinds.camera.linear,
  Cylindrical: kinds.camera.cylindrical,
  Planet: kinds.camera.planet,
  Pannini: kinds.camera.pannini
} as const

export type CameraProjectionKind = (typeof CameraProjection)[keyof typeof CameraProjection]

/**
 * Texture projection kinds, uploaded as `u_TexProjType`.
 *
 * Fisheye is deliberately absent. The legacy code carried a Fisheye constant
 * that was unreachable, a JS branch that threw, and a shader branch that
 * returned vec2(0.0) -- three mutually inconsistent descriptions of a feature
 * that does not exist. Describe what exists.
 */
export const TextureProjection = {
  Equirectangular: kinds.texture.equirectangular
} as const

export type TextureProjectionKind = (typeof TextureProjection)[keyof typeof TextureProjection]
```

`tsconfig.json` 需要 `"resolveJsonModule": true` —— 加上它。

`scripts/gen-shader-constants.mjs`：

```js
/*
 * Generates the shader-side projection constants from the single JSON source.
 *
 * WGSL has no preprocessor, so its constants are `const` declarations. GLSL ES
 * has #define. Both are emitted from the same JSON, which is the entire point:
 * in the legacy code these were two hand-maintained copies that happened to
 * agree.
 *
 * The output is committed. `npm run build` does not run this generator -- a
 * build that silently regenerates a source file makes a dirty working tree
 * look clean. Instead `verify-generated` fails if the committed output is
 * stale.
 *
 * Usage: node scripts/gen-shader-constants.mjs [--check]
 */

import { readFile, writeFile } from 'node:fs/promises'
import path from 'node:path'
import { fileURLToPath } from 'node:url'

const repoRoot = path.resolve(path.dirname(fileURLToPath(import.meta.url)), '..')
const sourcePath = path.join(repoRoot, 'src/core/projection-kinds.json')
const outPath = path.join(repoRoot, 'src/renderer/shaders/generated.ts')

const check = process.argv.includes('--check')

/** `linear` -> `LINEAR`; `equirectangular` -> `EQUIRECTANGULAR`. */
const screamingSnake = key => key.replace(/([a-z0-9])([A-Z])/g, '$1_$2').toUpperCase()

const kinds = JSON.parse(await readFile(sourcePath, 'utf8'))

const lines = []
lines.push('CAMERA_PROJECTION')
for (const [key, value] of Object.entries(kinds.camera)) {
  lines.push(`${screamingSnake(key)}=${value}`)
}
lines.push('TEXTURE_PROJECTION')
for (const [key, value] of Object.entries(kinds.texture)) {
  lines.push(`${screamingSnake(key)}=${value}`)
}

const wgsl = lines
  .filter(l => l.includes('='))
  .map(l => {
    const [name, value] = l.split('=')
    return `const ${name}: u32 = ${value}u;`
  })
  .join('\n')

const glsl = lines
  .filter(l => l.includes('='))
  .map(l => `#define ${l}`)
  .join('\n')

const content = `/*
 * GENERATED FILE -- DO NOT EDIT.
 *
 * Produced by scripts/gen-shader-constants.mjs from src/core/projection-kinds.json.
 * Edit the JSON and run \`npm run gen:shaders\`.
 *
 * Committed rather than built so that a stale value shows up as a failing
 * \`--check\` rather than as a working tree that quietly rewrites itself.
 */

/** WGSL declarations, prepended to the WGSL shader source. */
export const WGSL_CONSTANTS = ${JSON.stringify(wgsl + '\n')}

/** GLSL ES declarations, prepended to the GLSL shader source. */
export const GLSL_CONSTANTS = ${JSON.stringify(glsl + '\n')}
`

if (check) {
  const existing = await readFile(outPath, 'utf8').catch(() => null)
  if (existing !== content) {
    console.error('src/renderer/shaders/generated.ts is stale. Run: npm run gen:shaders')
    process.exit(1)
  }
  console.log('generated shader constants are up to date')
} else {
  await writeFile(outPath, content)
  console.log(`wrote ${path.relative(repoRoot, outPath)}`)
}
```

`src/core/validate.ts`：

```ts
/**
 * The range assertions that survived deleting `param-check`.
 *
 * Most of what `param-check` did is now the type system's job: "is this a
 * number" and "is this a Camera" are compile errors in TypeScript. What types
 * cannot express is *range* -- and range is what actually breaks this library,
 * because out-of-range angles and zero-length vectors produce matrices full of
 * NaN, which render as a black screen with no error anywhere.
 *
 * So this module is small on purpose. If you are tempted to add an
 * `isArray`-style check here, the answer is that the type signature is wrong
 * instead.
 */

/**
 * Clamps a latitude into `[-90, 90]` degrees.
 *
 * Latitude does not wrap. 100 degrees is not -80, it is "as far up as the
 * camera can go" -- wrapping would put the camera upside down, which is a
 * different picture, not a normalised one.
 *
 * @throws If `degrees` is not finite.
 */
export function clampLatitude (degrees: number): number {
  if (!Number.isFinite(degrees)) {
    throw new TypeError(`latitude must be finite, got ${degrees}`)
  }
  return Math.min(90, Math.max(-90, degrees))
}

/**
 * Normalises a longitude into `[0, 360)` degrees.
 *
 * The result is never exactly 360: `wrapLongitude(360)` is `0`. The legacy
 * non-linear cameras used `long % 25`, which is a different function with a
 * different range, and the linear path used `[0, 360)`. There is one answer now.
 *
 * @throws If `degrees` is not finite.
 */
export function wrapLongitude (degrees: number): number {
  if (!Number.isFinite(degrees)) {
    throw new TypeError(`longitude must be finite, got ${degrees}`)
  }
  return ((degrees % 360) + 360) % 360
}

/**
 * Asserts a value is strictly greater than zero and returns it.
 *
 * @param name - Argument name, used in the error message.
 * @throws If `value` is not finite or is not positive.
 */
export function assertPositive (value: number, name: string): number {
  if (!Number.isFinite(value) || value <= 0) {
    throw new RangeError(`${name} must be a finite number greater than 0, got ${value}`)
  }
  return value
}

/**
 * Asserts a value is finite and returns it.
 *
 * @param name - Argument name, used in the error message.
 * @throws If `value` is NaN or infinite.
 */
export function assertFinite (value: number, name: string): number {
  if (!Number.isFinite(value)) {
    throw new RangeError(`${name} must be finite, got ${value}`)
  }
  return value
}
```

- [ ] **Step 4: 写类型模块**

`src/core/types.ts`：

```ts
/**
 * The vocabulary shared by every layer.
 *
 * Nothing here knows about WebGL, WebGPU, the DOM, or depth conventions. That
 * is deliberate: `core` is the layer both backends agree on, so anything that
 * differs between them must not appear in these types.
 */

import type { CameraProjectionKind, TextureProjectionKind } from './constants'

/**
 * Camera orientation.
 *
 * Angles are degrees, matching the legacy public API. Nothing here is a
 * scale factor or a matrix -- those are derived, and storing them would create
 * a second source of truth that can disagree with the angles.
 */
export interface CameraState {
  /** Degrees, always in `[-90, 90]`. Use `clampLatitude`. */
  readonly povLatitude: number
  /** Degrees, always in `[0, 360)`. Use `wrapLongitude`. */
  readonly povLongitude: number
}

/**
 * How the projection maps view directions onto the screen.
 *
 * `extent` is the part the legacy code hid inside geometry. The three non-linear
 * projections are not scale-invariant: `theta = z * TWO_PI` reads the magnitude
 * of `z`, so the size of the surface being projected is part of the projection
 * itself. The legacy code baked it into quad vertex coordinates (1x1 for
 * cylindrical, 4x4 for planet and pannini) and the numbers never participated
 * in any other computation -- the shader declared `u_CamGeoWidth` and
 * `u_CamGeoHeight` and read neither.
 *
 * Promoting it to a parameter is what lets the geometry subsystem disappear.
 */
export type Projection =
  | { readonly kind: typeof CameraProjectionKind.Linear }
  | { readonly kind: 'linear'; readonly fov: number; readonly aspect: number }
  | { readonly kind: 'cylindrical'; readonly zoom: number; readonly extent: readonly [number, number] }
  | { readonly kind: 'planet'; readonly zoom: number; readonly extent: readonly [number, number] }
  | { readonly kind: 'pannini'; readonly zoom: number; readonly extent: readonly [number, number] }

/**
 * How the source image's pixels map onto directions in the world.
 *
 * This belongs to the source, not the camera. A camera does not know whether
 * the picture behind it is equirectangular or fisheye, and the legacy code got
 * this right -- `Camera.status()` emitted only `u_CamProjType` while the
 * renderer uploaded `u_TexProjType` separately.
 */
export type SourceProjection = 'equirectangular'

/**
 * Everything the renderer needs to know about the pixels it is sampling.
 */
export interface SourceState {
  readonly projection: SourceProjection
  readonly width: number
  readonly height: number
  /**
   * Set when the source is larger than the device's `maxTextureDimension2D` and
   * must be downscaled through an intermediate canvas first.
   */
  readonly frameSize?: readonly [number, number]
}

/** Depth clip range, which is the one thing the two backends genuinely disagree about. */
export type DepthRange = 'minus-one-to-one' | 'zero-to-one'
```

### Task 3: 矩阵构建与 P0 对拍

**Files:**

**这是 P2 的核心验收步骤。** P0 存下了旧实现每帧发给 GPU 的 `u_CamTransMatrix`。只要新实现吃同样的相机参数、吐出同样的数字，就证明了矩阵这一层没改坏 —— **且全程不需要 GPU**。

- [ ] **Step 1: 先读旧实现，把它做的事原样抄下来**

Run: `sed -n '1,200p' legacy/src/core/camera/LinearProjection.js`

重点是 `updateMatrix()`：它用 `viewMat_.setLookAt(0,0,0, cos(phi)*cos(theta), sin(phi), -cos(phi)*sin(theta), 0,1,0)` **把眼睛钉在原点、让世界转**，然后再乘投影矩阵。

**新实现必须复现这个约定**，包括那个 `-sin(theta)` 的负号 —— 它不是笔误，是旧实现的朝向约定，改了它画面会左右镜像。

`src/core/matrix.ts`：

```ts
/**
 * Matrix construction for both backends.
 *
 * The one thing that differs between WebGL and WebGPU is the depth clip range:
 * GL maps the near plane to -1 and the far plane to +1, WebGPU maps them to 0
 * and 1. Getting this wrong does not throw -- the picture renders with the far
 * half of the scene missing or inverted.
 *
 * The legacy code baked the GL convention into its matrix helpers, so the
 * convention was invisible at every call site. Here it is a parameter, and the
 * gl-matrix function that implements it has the convention in its name
 * (`perspective` vs `perspectiveZO`), so it cannot be selected by accident.
 */

import { mat4 } from 'gl-matrix'
import { CameraProjection } from './constants'
import type { CameraState, DepthRange, Projection } from './types'

/** Radius of the surface the legacy renderer projected onto. Kept only so the
 *  camera transform matches the baseline; see the note in `buildViewMatrix`. */
const LEGACY_WORLD_RADIUS = 100

const HALF_PI = Math.PI / 2

/**
 * Builds the view matrix: eye at the origin, world rotated by the camera angles.
 *
 * This is the legacy convention, and it is worth stating explicitly because it
 * looks backwards. The legacy viewer never moves the camera -- it rotates the
 * world around a stationary eye, which is why `setLookAt` is called with a
 * zero eye position and a direction vector derived from the angles.
 *
 * The `-sin(theta)` in the target's X component is not a typo. It is the legacy
 * handedness, and flipping it mirrors the panorama horizontally.
 *
 * @param state - Camera angles in degrees.
 * @param out - Destination matrix.
 */
export function buildViewMatrix (state: CameraState, out: mat4): mat4 {
  const theta = (state.povLongitude * Math.PI) / 180
  const phi = (state.povLatitude * Math.PI) / 180

  return mat4.lookAt(
    out,
    [0, 0, 0],
    [Math.cos(phi) * Math.cos(theta), Math.sin(phi), -Math.cos(phi) * Math.sin(theta)],
    [0, 1, 0]
  )
}

/**
 * Builds a projection matrix in the requested depth convention.
 *
 * @param projection - The projection to build. `zoom` is folded in here rather
 *   than applied by the shader so that the linear path, which has no zoom
 *   uniform, behaves the same way as the others.
 * @param depth - Which backend's depth clip range to produce.
 * @param out - Destination matrix.
 */
export function buildProjection (
  projection: Projection,
  depth: DepthRange,
  out: mat4
): mat4 {
  const zo = depth === 'zero-to-one'

  if (projection.kind === CameraProjection.Linear) {
    return zo
      ? mat4.perspectiveZO(out, projection.fov, projection.aspect, NEAR, FAR)
      : mat4.perspective(out, projection.fov, projection.aspect, NEAR, FAR)
  }

  // The three non-linear projections are computed per-fragment from the
  // camera's own parameters; their matrix is an orthographic box whose aspect
  // the shader does not read. Keeping it orthographic means the fullscreen
  // triangle covers the clip volume exactly.
  return zo
    ? mat4.orthoZO(out, -1, 1, -1, 1, NEAR, FAR)
    : mat4.ortho(out, -1, 1, -1, 1, NEAR, FAR)
}

/** Near and far planes. The legacy cube sat at radius 100 and was the only
 *  geometry, so these bound it with room to spare. */
const NEAR = 0.1
const FAR = 1000

/**
 * Builds the matrix uploaded as `u_CamTransMatrix`.
 *
 * Equivalent to `projection * view`, in that order.
 */
export function buildCameraTransform (
  state: CameraState,
  projection: Projection,
  depth: DepthRange,
  out: mat4
): mat4 {
  const view = mat4.create()
  const proj = mat4.create()
  buildViewMatrix(state, view)
  buildProjection(projection, depth, proj)
  return mat4.multiply(out, proj, view)
}
```

`src/core/reference.ts`：

```ts
/**
 * A float64 CPU implementation of the four projections.
 *
 * Why this exists: the cross-backend pixel test compares WGSL against GLSL, and
 * it has a blind spot -- if both shaders were written from the same
 * misunderstanding, they agree with each other and the test passes. This module
 * is the independent third opinion. It is the only artifact in the repo that can
 * catch "both backends are wrong in the same way".
 *
 * It is also the definition of the legacy coordinate ranges, which gate B in P3
 * checks the affine remap against.
 *
 * Everything here is transcribed line by line from legacy/src/shader/fshader.glsl
 * and must stay that way. If the shader changes, this changes with it -- the
 * parity test in test/unit/reference.test.ts is what makes that a requirement
 * rather than a good intention.
 */

import { CameraProjection } from './constants'
import type { CameraState, Projection } from './types'

const HALF_PI = Math.PI / 2
const TWO_PI = Math.PI * 2

/** An equirectangular texture coordinate in `[0, 1]`. */
export interface UV {
  readonly u: number
  readonly v: number
}

/**
 * GLSL's `mod`, which always returns a value with the sign of the divisor.
 *
 * JavaScript's `%` truncates toward zero instead, so `-0.25 % 1` is `-0.25`
 * where GLSL gives `0.75`. Every wrap in the shader relies on the GLSL
 * behaviour, so using `%` directly would introduce a seam at the antimeridian
 * that only shows up at some camera angles.
 */
function glslMod (x: number, y: number): number {
  return ((x % y) + y) % y
}

/**
 * The linear (perspective) projection.
 *
 * Scale-invariant: multiplying `(x, y, z)` by any positive constant leaves the
 * result unchanged, because every term is a ratio. This is the property that
 * lets the geometry subsystem be replaced by a single fullscreen triangle --
 * the surface being rasterised contributes direction only.
 */
function projectLinear (x: number, y: number, z: number): UV {
  const theta = Math.atan2(z, x)
  const phi = Math.atan(y / Math.sqrt(x * x + z * z)) + HALF_PI
  return { u: glslMod(theta / TWO_PI + 0.5, 1), v: phi / Math.PI }
}

/*
 * The three non-linear projections below are NOT scale-invariant: they read the
 * magnitude of their inputs, not just their ratio. That is why the size of the
 * surface being projected is a projection parameter (`extent`) and not a
 * property of geometry.
 */

function projectCylindrical (x: number, y: number, z: number, zoom: number, lng: number): UV {
  // x is deliberately unread. In the legacy quad it was pinned at 1, so it was
  // a constant, and the projection depends only on the other two axes.
  const yy = y * zoom
  const zz = z * zoom
  const theta = zz * TWO_PI - lng / 2
  const phi = Math.atan(yy) + HALF_PI
  return { u: glslMod(theta / TWO_PI + 0.5, 1), v: phi / Math.PI }
}

function projectPlanet (x: number, y: number, z: number, zoom: number, lng: number): UV {
  const zz = z * zoom
  const yy = y * zoom
  const m = 1 + zz * zz + yy * yy
  const p = (2 * zz) / m
  const q = (2 * yy) / m
  const r = (m - 2) / m
  let theta = Math.atan2(p, q)
  theta = glslMod(theta, TWO_PI)
  theta -= lng / 2
  const phi = Math.atan(r / Math.sqrt(p * p + q * q)) + HALF_PI
  return { u: glslMod(theta / TWO_PI + 0.5, 1), v: phi / Math.PI }
}

function projectPannini (x: number, y: number, z: number, zoom: number, lng: number): UV {
  const theta0 = Math.atan2(z * 0.5 * zoom, x)
  const theta = theta0 * 2 - lng / 2
  const phi = Math.atan(y / Math.sqrt(x * x + z * z)) + HALF_PI
  return { u: glslMod(theta / TWO_PI + 0.5, 1), v: phi / Math.PI }
}

/**
 * Projects a point on the camera's surface to an equirectangular coordinate.
 *
 * @param x - Surface position. For the linear projection only the direction
 *   matters; for the others the magnitude is part of the projection.
 * @param state - Camera angles, used by the non-linear projections as a
 *   longitude offset.
 * @param projection - Which formula to apply.
 */
export function project (x: number, y: number, z: number, state: CameraState, projection: Projection): UV {
  const lng = (state.povLongitude * Math.PI) / 180

  switch (projection.kind) {
    case CameraProjection.Linear:
      return projectLinear(x, y, z)
    case CameraProjection.Cylindrical:
      return projectCylindrical(x, y, z, projection.zoom, lng)
    case CameraProjection.Planet:
      return projectPlanet(x, y, z, projection.zoom, lng)
    case CameraProjection.Pannini:
      return projectPannini(x, y, z, projection.zoom, lng)
  }
}

/**
 * Maps a normalised device coordinate to the surface position the projection
 * formulas expect.
 *
 * This replaces the legacy quad. There, a quad sized `extent` was rasterised and
 * the interpolated vertex position was fed to the projection; the only thing
 * that varied across the quad was its `(y, z)` pair, and `x` was pinned at 1.
 * This is that same affine map, written down.
 *
 * @param ndcX - Horizontal device coordinate in `[-1, 1]`.
 * @param ndcY - Vertical device coordinate in `[-1, 1]`.
 * @param extent - Half-size of the surface, matching the legacy quad.
 */
export function ndcToSurface (
  ndcX: number,
  ndcY: number,
  extent: readonly [number, number]
): readonly [number, number, number] {
  // The quad lay in the x = 1 plane, spanning y and z. NDC y maps to world y
  // and NDC x maps to world -z, matching the legacy vertex ordering.
  return [1, (ndcY * extent[1]) / 2, (-ndcX * extent[0]) / 2]
}
```

> **`ndcToSurface` 的映射方向是这个任务里唯一需要推演的地方。** 它必须与旧四边形顶点顺序一致，而**门禁 B 正是用来确认它的**。写完之后先跑 Step 3 的齐次性测试确认线性路径对，非线性路径的方向留到 P3 门禁 B 定案。**如果推不出来，不要瞎猜 —— 把这一步作为卡点上报**，附上 `legacy/src/core/camera/CylindricalCamera.js` 里 `new Polygon([...])` 的四个顶点坐标。

    // panorama that only appears at some longitudes.
    const projection: Projection = { kind: CameraProjection.Cylindrical, zoom: 1, extent: [1, 1] }
    const uv = project(1, 0, 0.5, { povLatitude: 0, povLongitude: 350 }, projection)
    expect(uv.u).toBeGreaterThanOrEqual(0)
    expect(uv.u).toBeLessThanOrEqual(1)
  })
})
